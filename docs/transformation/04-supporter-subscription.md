## 2. Реализация (сервер, миграция `kh/billing/supabase/036_supporter.sql`, новая, повторяемая)

| Объект | Назначение |
|---|---|
| `supporter_config` (RLS, всё отозвано) | `price_month` 5000, `currency` KZT, `max_months` 12, **`payments_enabled` = false по умолчанию** |
| `accounts.supporter_until`, `supporter_cancel_at` | оплаченный безрекламный период; заявка на отмену. Клиент записать не может (нет UPDATE-прав; тест) |
| `invoices.kind = 'supporter'` | счёт идёт по уже проверенному пути: вебхук → `payment_received` → `confirm_invoice_core`. Уникальный индекс «один открытый счёт» разделён: supporter и legacy счёт могут сосуществовать |
| `confirm_invoice_core` (обёртка) | для `supporter` продлевает `supporter_until` (прибавляя к концу периода, если он в будущем, иначе от «сейчас»), снимает заявку на отмену; **не трогает** `paid_until`, `store_limit`, скидки, рефералку. Остальные виды счетов уходят в прежнюю логику, переименованную в `confirm_legacy_invoice_core` |
| `get_entitlements()` | **единственный** источник «показывать рекламу»: из БД по `auth.uid()`; клиент не передаёт ни план, ни дату, ни «я оплатил». Возвращает `status` (`free`/`supporter`/`supporter_ending`/`expired`), `ad_free`, `show_ads`, `ends_at`, `restricts_functionality: false`, свой открытый supporter-счёт |
| `legacy_paid_until(uid)` | максимум `period_to` **оплаченных** счетов `manual/renewal`. Пробный период, дни рефералки и ручные начисления админа безрекламности не дают |
| `create_supporter_invoice(months, phone)` | нужна принятая оферта и `supporter_payments_ready()`; сумма считается на сервере; повторный тот же запрос возвращает тот же счёт; другой срок заменяет открытый |
| `cancel_supporter()` / `resume_supporter()` | отмена: открытый счёт отменяется, отметка «не продлевать», период доживает до конца. Продление никогда не автоматическое |
| `payment_failed(...)` (только `service_role`) | уведомление провайдера о неудаче: пишется один раз (`failed:<id>`), **ни права, ни счёт не меняет** (счёт остаётся `pending`, можно оплатить снова). Если провайдер «сообщает неудачу» по уже подтверждённому платежу — запись попадает в очередь админа с причиной `reversed` |
| `admin_set_supporter_payments(bool)` | `is_admin()`; включение при пустых QR и инструкциях → `payment_config_missing` |
| `get_license` (патч на месте) | `pending_invoice` теперь только legacy-счёт (иначе две строки подзапроса — см. находку F1) |
| `grants.sql` | добавлены 5 функций для `authenticated` и `payment_failed` для `service_role` |

### Состояния
| Состояние | Как достигается | Реклама |
|---|---|---|
| Активация | подтверждённый платёж (вебхук или `admin_confirm_invoice`) | нет |
| Продление | новый счёт и платёж; срок прибавляется к концу | нет |
| Отмена | `cancel_supporter()` → `supporter_ending` | нет до конца периода |
| Истечение | `supporter_until` в прошлом → `expired` (вычисляется, ничего не списывается) | да |
| Неудачный платёж | `payment_failed`; счёт `pending` | без изменений |
| Дубль уведомления | `unique(provider, payment_id)` → тот же ответ, `duplicate: true`, ничего не меняется | — |
| Второй платёж за уже оплаченный счёт | `invoice_not_pending` → очередь админа, период не удваивается | — |
| Неверная сумма | `amount_mismatch` → очередь админа | — |

## 3. Legacy-клиенты (без автосписаний)

- Ничего не списывается, не конвертируется, не пересчитывается; `get_entitlements` ничего не создаёт и не пишет (тест: строка аккаунта и число счетов до/после совпадают).
- **Оплаченный период сохраняется:** пока не истёк `period_to` оплаченного счёта, аккаунт безрекламный (`legacy_paid_until`). После этого — обычный FREE, функции прежние.
- Открытые legacy-счета остаются как есть; `create_invoice` больше не отменяет supporter-счёт.
- Историю (`invoices`, `payment_events`, `paid_until`, `store_limit`) миграция не меняет.
- Решения владельца: (а) `create_invoice` всё ещё доступен через RPC (Stage 03); оплаченный по нему счёт даст безрекламность на срок — рекомендуется отозвать право или ограничить датой вступления 036 (находка F6); (б) юридические тексты (`legal/offer.html`, `terms.html`) и `billing/README.md` всё ещё содержат старые тарифы и требуют правки владельцем [не сделано].
