## 1. Что сделано

Один слот `#adSlot` в `dashboard.html`: **шапка (`.topbar`) → строка «обновлено» → баннер → системные уведомления → страница**. В `popup`, `print.html` и экране упаковщика баннера нет (в режиме упаковщика слот скрыт и запросов нет).

| Требование | Реализация |
|---|---|
| Один баннер | один `<section id="adSlot">`, один `.ad-banner`; тест считает элементы |
| Высота | desktop 72 px, ≤760 px — 56 px, фиксированная (контент обрезается многоточием, а не растёт) |
| ≤ 3 кампаний | сервер (триггер, Stage 05) + `slice(0,3)` в `resolveAds` и в `createRotation` |
| Смена каждые 30 с | `createRotation` (таймер-цепочка, `ROTATE_MS = 30000`) |
| Ручная навигация | кнопки «назад / вперёд», счётчик «1 / 3» |
| Пауза «когда уместно» | вкладка скрыта; курсор мыши над баннером; клавиатурный фокус внутри (`:focus-visible`); кнопка «пауза/продолжить»; `prefers-reduced-motion` (автосмены нет вообще). После снятия паузы объявление получает полный интервал 30 с |
| Пометка рекламы | бейдж «Реклама» (kk: «Жарнама») + имя спонсора; внутренний контент помечен «SaudaPulse», не «Реклама» |
| Supporter не видит рекламу | `resolveAds` одновременно спрашивает `ui:supporterGet` и `ui:adsGet`; `adFree`/`showAds:false` из любого ответа → слот скрыт, ни одного рекламного узла, события не отправляются. Сервер (`get_ads`) и воркер (`billing.ads`) проверяют то же самое (Stage 04/05) — это третья проверка |
| Без сдвигов вёрстки | фиксированная высота; при загрузке — скелетон той же высоты, **если прошлый показ был с рекламой** (раздел 6, п. 1) |
| Состояния | loading (скелетон + `aria-busy`), ready, empty/error/adfree/off → слот `hidden`, 0 высоты, никакого текста об ошибке |
| Внутренняя реклама | приходит с сервера как `fallback` (Stage 05, ≤3, только хосты `internal_hosts`); рисуется как обычная, с пометкой «SaudaPulse» |
| Сбой не мешает работе | `resolveAds` никогда не бросает; таймаут 8 с; запрос не ожидается бизнес-кодом; `mountAdBanner` обёрнут в `try/catch`; повтор через 60 с и 120 с (макс. 2) |
| Аналитика | точка расширения `onEvent(event, ad)`; по умолчанию — `ui:adsEvent` → `{id, event}` (агрегатный счётчик Stage 05). Показ — один раз на кампанию за загрузку страницы, только когда вкладка видна и баннер показан; клик (включая среднюю кнопку). Ничего о магазинах, заказах, покупателях не отправляется (тест проверяет ключи `event,id`) |
| Запрещено | нет полноэкранных/интерстициальных, нет принудительных кликов (обычная ссылка, `target=_blank`, `rel="noopener noreferrer sponsored"`, `referrerpolicy=no-referrer`), нет анимаций (смена мгновенная, без transition), блокировки функций нет, коммерческие данные не читаются |

Безопасность содержимого: тексты — только текстовые узлы (`h()`), ссылки и картинки только `https://`, сломанная картинка удаляет себя (дыры нет).

Доступность: `role="group" aria-roledescription="carousel"` с названием, каждый слайд `slide` «Объявление n из N», все кнопки с именами и `title`, цели ≥ 32 px, постоянная скрытая область `role="status"` — ручная навигация озвучивается, автосмена молчит; фокус возвращается на ту же кнопку/ссылку после перерисовки; `forced-colors` рамка фокуса; текст «откроется в новой вкладке» для скринридера; ru/kk (`ads.*`, 10 ключей, тест локалей зелёный).

## 6. Ограничения и решения владельца

1. **Резервирование места.** Скелетон показывается только если прошлый показ был с рекламой (флаг в `localStorage`, один на браузер). Первый показ у free-пользователя вставляет баннер и сдвигает страницу вниз один раз; противоположный случай — устаревший флаг — даёт скелетон до 8 с, который затем схлопывается (supporter после смены аккаунта на том же браузере). Альтернатива — резервировать всегда, но тогда supporter видит пустую рамку при каждой загрузке; выбрал не показывать пустоту supporter'ам.
2. **Внутренняя реклама только с сервера.** Если сервер вернул пустой список (рекламная система выключена, сбой), слот схлопывается; зашитого в клиент объявления нет, чтобы не обойти выключатель `ads_enabled` и не показать ничего пользователю с неизвестным статусом. Состояние `error` почти недостижимо: воркер превращает ошибки RPC в пустой список (`billing.js`).
3. **Реклама стоит над системными уведомлениями** (о блокировке кабинета, истечении подписки) и сдвигает их на 72/56 px — так требует ТЗ («сразу под шапкой»). Если владелец захочет, слот можно поставить после `#banners` одной строкой в HTML.
4. **Счётчики показов приблизительные:** считается показ при видимой вкладке, а не пересечение с окном просмотра (при прокрутке баннер уезжает вместе со страницей). Не использовать для расчётов со спонсорами (как и в Stage 05).
5. **Не проверялось на живом Supabase и с реальными креативами.** В e2e ответы воркера подменены; путь воркер → RPC покрыт тестами Stage 05. Картинка в скриншотах — заглушка.
6. **Включение по-прежнему требует блокеров Stage 05**: хост креативов, проверка содержимого картинок, вкладка админки, правка политики конфиденциальности/оферты, `admin_ad_config(true, …)`.
7. Только Chromium (Playwright). Firefox, Safari, реальный скринридер не проверялись. Люди с `prefers-reduced-motion` и клавиатурой смоделированы, не проверялись вживую.
8. Существующие наборы `devices.js`, `uishots.js` и другие работают на копии `tests/apicopy`, не на исходниках; их регресс **не** перезапускался. Горизонтальная прокрутка и меню на 4 ширинах проверены в `adbanner.js`.
9. `CLS` страницы ≈ 0,011 при загрузке — это существующий сдвиг `nav/topbar/sidebar` при первом применении i18n (в журнале `stage06-e2e` источники — не баннер и не `#view`); баннер сдвигов не вносит.
10. Лишний запрос: каждая загрузка дашборда вызывает `ui:supporterGet` (кэш воркера 10 мин) параллельно с `ui:adsGet`.

## 7. Статус

**Готово в песочнице, не развёрнуто.** Критерии: один баннер под шапкой — да; 60–80 / 50–60 px — да; ≤ 3 кампаний, 30 с, ручная навигация, паузы (вкладка, наведение, фокус, кнопка, reduced-motion) — да; пометка «Реклама» — да; supporter не видит рекламу — да (три независимые проверки, тест на открытой вкладке); loading/empty/error — да; внутренний fallback — только серверный (п. 2); сбои рекламы не влияют на бизнес-функции — да (тесты навигации при каждом сбое); точки аналитики без персональных данных — да; запрещённых форматов нет.
