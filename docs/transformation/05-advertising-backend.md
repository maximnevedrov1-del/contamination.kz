## 1. Архитектура

```
admin (is_admin) ──admin_ad_save/set_status/config/list/stats──▶ ad_campaigns  ◀── trigger ad_campaigns_guard
                                                                   │            (лимит 3, эксклюзив категории,
                                                                   │             URL/даты/хосты, advisory lock)
extension SW ──ui:adsGet──▶ get_ads() ── get_entitlements().show_ads (Stage 04) ──▶ [] для ad-free
             ──ui:adsEvent─▶ ad_record() ─▶ ad_stats (суточные счётчики, без пользователя)
```

- **Эксклюзивность и лимит живут на сервере**, в триггере (`ad_campaigns_guard`), поэтому действуют и для прямого SQL, и для любых RPC; сериализуются `pg_advisory_xact_lock`, гонки к 4-й кампании нет (проверено двумя параллельными сессиями, раздел 7).
- **Допуск к рекламе** = `get_entitlements()->>'show_ads'` из Stage 04 (активный supporter или оплаченный legacy-период → рекламы нет). Отдельной логики тарифов нет.
- **Изоляция сбоев:** `get_ads()` и `ad_record()` перехватывают любую внутреннюю ошибку и отвечают пустым списком/`false`; клиент (`ads()`, `adEvent()`) никогда не бросает исключение и нигде не ожидается бизнес-кодом. Ни одна функция этого этапа не вызывает `has_access`, `store_cap`, `ensure_price_feed`.

## 2. База данных (`kh/billing/supabase/037_advertising.sql`, новая, повторяемая)

| Объект | Назначение |
|---|---|
| `ad_config` (id=1, RLS, всё отозвано) | `ads_enabled` (**false**), `asset_hosts` (**пусто**), `internal_hosts` (`saudapulse.kz`, `www.saudapulse.kz`) |
| `ad_campaigns` | `id`, `kind` (`sponsor`/`internal`), `sponsor_name`, `category` (slug), `headline`, `body`, `creative_url`, `creative_alt`, `destination_url`, `starts_at`, `ends_at`, `status` (`draft`/`active`/`suspended`/`expired`), аудит `created_by/updated_by`. CHECK: спонсору нужны категория, картинка и дата конца; окно ≤ 366 дней; внутренняя реклама без категории |
| `ad_stats` | `(campaign_id, day, impressions bigint, clicks bigint)` — **только агрегаты**, без пользователя |
| `ad_valid_url(text, image)` | https, схема строго в нижнем регистре, DNS-имя с буквенным TLD (нет IP, `localhost`, userinfo, порта, пробелов, `#`), ≤ 500 символов, хост ≤ 253, запрещены TLD `local/localhost/internal/lan/corp/home/test/invalid/example`; картинки: только `png/jpg/jpeg/webp`, **без query** (нет трекинг-пикселей), без SVG |
| `ad_campaigns_guard()` (trigger) | валидация URL; для `active`: окно дат, хост картинки ∈ `asset_hosts`, **не более 3 активных спонсоров**, **одна активная кампания на категорию**; просроченные `active` гасятся перед проверкой; fail-closed на NULL-хост |
| `expire_ad_campaigns()` | истечение по `ends_at` (вызывается из `get_ads` и админ-функций; можно запускать по расписанию, `service_role`) |
| `admin_ad_list/save/set_status/config/stats` | `is_admin()` первой строкой, `SECURITY DEFINER`, `search_path = public`; `save` читает только белый список ключей, статус через `save` задать нельзя |
| `get_ads()`, `ad_record()` | клиентские точки (authenticated) |
| `grants.sql` | все новые функции перечислены; helpers и триггер отозваны у всех |

**Жизненный цикл:** `draft → active ⇄ suspended`, любое → `expired` (финально; повтор — новой кампанией). Активация/правка активной кампании каждый раз проходит полную проверку триггера. Приостановка и истечение выполняются всегда (даже если владелец позже сменил белые списки), пока URL не менялись.

## 3. API

| Endpoint (RPC) | Кто | Ответ |
|---|---|---|
| `get_ads()` | вошедший пользователь | `{show_ads, ads:[≤3 {id, kind, sponsor_name, headline, body, creative_url, creative_alt, destination_url}], fallback}`; без категории, статуса, аудита. Спонсоры (≤3) → если нет ни одного доступного, внутренние (`fallback: true`). Ad-free, выключенная система, любая ошибка → `ads: []` |
| `ad_record(campaign, 'impression'\|'click')` | вошедший | `true` только если кампания сейчас отдаётся, система включена и пользователь не ad-free; +1 к суточному счётчику |
| `admin_ad_list(status?)`, `admin_ad_save(id?, json)`, `admin_ad_set_status(id, status)`, `admin_ad_config(enabled?, asset_hosts?, internal_hosts?)`, `admin_ad_stats(id?, days)` | только админ | JSON |

Клиент: `ui:adsGet`, `ui:adsEvent` (service worker), `ads()`/`adEvent()` (`background/billing.js`, кэш 15 мин на пользователя, очищается при выходе), `normalizeAds()` (`shared/ads.js`) — **вторая независимая проверка** того, что прислал сервер.

## 4. Контроли безопасности

- Авторизация: все `admin_*` проверяют `is_admin()`; таблицы закрыты (RLS без политик, права отозваны); клиент не читает и не пишет `ad_*`; `anon` не вызывает ничего (тесты, `has_function_privilege`).
- Валидация ссылок и картинок в БД (регэксп + триггер) и повторно в клиенте; белый список хостов картинок (по умолчанию пуст — ни одна картинка спонсора не может выйти в эфир, пока владелец не задаст хост); внутренняя реклама ведёт только на `internal_hosts`.
- Приватность: `get_ads` ничего не пишет и не логирует; счётчики — агрегаты `campaign/day`; в запросах нет данных заказов, товаров, клиентов, поставщиков, прибыли, выручки и маркетплейс-ключей (клиент отправляет только id кампании и тип события); клик открывает URL спонсора напрямую (без редиректа через нас); сторонних скриптов и трекеров нет; тест проверяет, что у `ad_stats` ровно колонки `campaign_id, day, impressions, clicks`, а у `ad_campaigns` нет колонок с `user/order/customer/product/supplier/price/revenue/token/email`.
- Бизнес-функции не ограничиваются: тесты проверяют, что при сломанном рекламном бэкенде и при включённой рекламе `ensure_price_feed`, `get_license`, `get_entitlements` работают одинаково для free и supporter.
