# Админ-панель Kaspi Seller Hub — инструкция владельцу (22.11.2026)

## 1. Где она и как открыть
- Файлы: `kaspi-seller-hub/billing/admin/` (`index.html`, `admin.js`, `admin.css`).
- Открыть: двойной клик по `billing/admin/index.html` (откроется в браузере как файл, сервер не нужен).
- При первом запуске введите:
  - Project URL: `https://zraktrilvwrfpcbmkqwi.supabase.co`
  - Publishable (anon) key: Supabase → проект → Settings → API.
  Они сохраняются в браузере (localStorage), повторно вводить не надо.
- Вход: ваш email → придёт код на почту → введите код. Новых пользователей вход не создаёт.
- Храните файл только локально. Не выкладывайте панель на хостинг и не отправляйте в магазин расширений (в сборки сайта и релиза её нет, проверено). Доступ даёт только запись в `public.admins`, но публичная страница лишняя поверхность атаки.

## 2. Как сделать себя админом
1. Один раз войдите в расширение (или в панель, шаг входа по коду) своей почтой, чтобы вы появились в `auth.users`.
2. Supabase → проект `zraktrilvwrfpcbmkqwi` → SQL Editor:
```sql
insert into public.admins (user_id)
select id from auth.users where email = 'YOUR_EMAIL'
on conflict do nothing;
```
(таблица `admins` имеет одну колонку `user_id uuid primary key`.)
3. Проверка:
```sql
select a.user_id, u.email from public.admins a join auth.users u on u.id = a.user_id;
```
4. Убрать админа:
```sql
delete from public.admins where user_id = (select id from auth.users where email = 'YOUR_EMAIL');
```
Если после входа панель пишет «forbidden», вы не в `admins` (или вошли другой почтой).

## 3. Что умеет панель, по вкладкам
- **Пульт**: где продавцы застревают (воронка), использование функций, удержание, NPS, причины ухода, список клиентов в зоне риска. Период 7/30/90/365 дней.
- **Ждут оплаты**: счета в статусе «ждёт оплаты». Порядок: в Kaspi Pay выставьте клиенту счёт на его номер на указанную сумму (или проверьте оплату по QR), затем «Оплата получена» (можно добавить заметку, например номер операции). «Отменить» отменяет счёт. Подтверждение продлевает подписку; клиент увидит это в расширении при ближайшей проверке. Каждые 30 с панель проверяет новые счета (счётчик в заголовке вкладки и уведомление).
  - Реферальная плашка на счёте (нужны миграции 019 и 021): «Реферал: <email> · пригласившему +14 дн. при подтверждении» / «бонус уже начислен» / «бонус не положен (доп. магазины)».
- **Оплаченные** и **Все счета**: история, поиск по email, телефону, номеру счёта.
- **Клиенты**: статус (пробный / оплачен / закончился), срок, магазины, последний визит, согласие с условиями, кнопка «+ дни» (подарить дни: компенсация или продление пробного, 1–366). Также код клиента, число приглашённых, бонусные дни и «пришёл по ссылке <email>» (нужны 019 и 021).
- **Вопросы**: обращения в поддержку, ответ клиенту.
- **Состояние**: здоровье сервиса, настройки бота и ops, ключ бота (BOT_KEY создаётся здесь кнопкой «Создать ключ бота», показывается один раз, его кладут в секреты функции и в GitHub), системный баннер для всех клиентов (до 300 символов).
- **Фича-флаги**: включение и выключение функций для клиентов.
- **Цены и QR**: цены, пробный период (дней и магазинов), лимиты, напоминания, grace и freeze, QR для оплаты.

Чего нет (честно):
- Кнопки «заморозить / заблокировать клиента» в панели нет. Заморозку (`frozen_until`) включает сам клиент в расширении («пауза»), длительность задаёт `freeze_days` на вкладке «Цены и QR». В «Клиентах» виден только бейдж `trial_blocked` («пробный уже был на этом магазине»). Заморозить вручную можно только SQL.
- Удаление аккаунта и purge просроченных (`admin_delete_account`, `admin_purge_expired`) в UI не выведены, только через SQL.
- У Telegram-бота нет админ-команд: он только присылает уведомления продавцам (`/start <токен>`, `/stop`). Ключ BOT_KEY нужен для запуска `/run` и создаётся на вкладке «Состояние».

## 4. Совместимость и порядок применения миграций
- Панель совместима с 018 (пробный 14 дней: в `admin.js` число 14 не зашито, срок берётся из `trial_days` и `trial_ends_at`), 019, 020 (`admin_invoices` — SECURITY DEFINER, отзыв колонок `admin_note`/`confirmed_by` на таблице его не затрагивает) и 021.
- Live-БД `zraktrilvwrfpcbmkqwi`: применены 017 и 018. **019, 020 и 021 ещё не применены.** Применять строго по порядку: **019 → 020 → 021** (SQL Editor, вставить файл целиком, либо попросите Claude применить).
- Что не работает до применения:
  - до 019: рефералов нет вообще;
  - до 021: панель работает как раньше, но реферальных плашек и полей на клиентах нет (панель это терпит, поля просто отсутствуют);
  - до 020: бонус за доп. магазины и бонус замороженному пригласившему ещё начисляются, колонки счетов не скрыты от клиентов.
