## Блокеры запуска (P0)

1. **Ветка не влита в `main`: 99 коммитов впереди, 0 позади.**
   - GitHub Pages собирает сайт из `main`, а там старая версия.
   - Cron-задачи `seller-hub-ops-alert.yml` (каждые 10 мин), `seller-hub-db-backup.yml` (02:17 по Алматы) и `seller-hub-bot.yml` GitHub запускает только из ветки по умолчанию. Значит, **рассылки бота, алерты и бэкапы БД сейчас не работают**.
   - Что сделать: открыть PR в `main` и влить его.
2. **Домен.** `CNAME` по-прежнему указывает на `contamination.kz`, и в корневом `index.html` 6 упоминаний «Contamination». При этом `externally_connectable`, оферта, политика и почта завязаны на `saudapulse.kz`.
   - Что сделать: перенести сайт на `saudapulse.kz` (`CNAME` и сборка из `kaspi-seller-hub/dist/site`) и убедиться, что открываются `/offer` и `/privacy`. Без живых страниц оферты и политики Chrome Web Store не пропустит расширение.
3. **Пустые `extensionId` и `storeUrl` в `site.config.json`.** Пока они не заполнены, главная кнопка сайта ведёт на `#support`, а мост `OPEN_DASHBOARD` не работает. Их можно заполнить только после публикации в Chrome Web Store.
4. **Секреты GitHub.** Нужны `SUPABASE_SERVICE_ROLE_KEY` (ops-alert после миграции 017), `OPS_KEY`, `BOT_KEY`, `TELEGRAM_*` и секреты для бэкапа. Без них workflow упадут даже после выкладки в `main`.
5. **401 в проде не подтверждён.** Бот v6 задеплоен, но прокси контейнера не пускает запросы к Supabase. Проверить вручную:
   ```bash
   curl -s -o /dev/null -w '%{http_code}' -X POST https://zraktrilvwrfpcbmkqwi.supabase.co/functions/v1/telegram-bot -d '{}'
   ```

## Важно (P1)

6. **Оплата вручную.** Каждый счёт Kaspi Pay админ подтверждает вручную через `admin_confirm_invoice`. Это узкое место после первых десятков клиентов.
7. **Импорт бэкапа не покрыт тестами.**
   - Сейчас импорт проверяет только `app` и `version` у файла и `sections` у каждого магазина. Содержимое заказов внутри не проверяется.
   - Заказы восстанавливаются только в магазины, где их ещё нет.
   - Что сделать: добавить unit-тест (экспорт → импорт → сравнение) и ограничение размера файла. Заказы вместе с фото могут весить десятки МБ.
8. **Supabase Auth: защита от утёкших паролей выключена.** Вход по OTP, поэтому риск низкий, но включение занимает один клик.
9. **PITR и бэкапы.** Не проверено, включён ли PITR. Workflow бэкапа не заработает, пока его нет в `main` и не заданы секреты.

## Можно улучшить (P2)

10. **`dashboard/dashboard.js` занимает 3415 строк.** Стоит разбить на модули по примеру `catalog-view`, `growth-view` и `staff-view`.
11. **Расхождение в истории миграций.** Миграция 009 записана в БД как `001_billing_revoke_fix`, хотя файл в репозитории называется `009_billing_revoke_fix.sql`.
12. **Advisor «RLS enabled, no policy» на 20 таблицах.** Это намеренно (доступ закрыт для всех, кроме RPC), но стоит записать в README, чтобы никто не «чинил».
13. **58 RPC с `SECURITY DEFINER` доступны `authenticated`.** Так задумано: функции `admin_*` проверяют `is_admin()`, остальные — `auth.uid()`. Стоит раз в релиз прогонять SQL-тесты, они это покрывают.
14. **Локальный мусор: 1,4 ГБ профилей Chrome в `tests/e2e/*prof*`.** В git они не попадают, но занимают диск. Их можно удалить.
15. **WhatsApp поддержки не заполнен** ни в `SUPPORT.whatsapp`, ни в `site.config`. Для селлеров в Казахстане это основной канал связи.
