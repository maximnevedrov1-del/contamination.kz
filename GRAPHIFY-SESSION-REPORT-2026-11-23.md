## 3. Проверка обещания «токен не уходит на сервер»

Граф связал обещание на лендинге с диалогом подключения магазина и модулем хешей. Проверено по коду:

- Токен проверяется у Kaspi, шифруется AES-GCM и хранится локально (`background/service-worker.js`, `ui:connectApi`).
- Токен уходит только на домен Kaspi; любой другой адрес блокируется (`background/kaspi-api.js:101`, ошибка `badUrl`).
- На сервер уходит только двойной SHA-256 от токена — для «одного пробного периода на магазин» (`shared/store-key.js`). Восстановить токен из него нельзя.
- В локальную резервную копию токены не попадают (`background/catalog-service.js`, `ui:backupExport`).

**Вывод:** обещание выполняется. Можно уточнить одну формулировку: сайт и политика пишут «хеши ID магазинов», а для API-магазинов это хеш, вычисленный из токена.
